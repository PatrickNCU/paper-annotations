# 譯文只在原文改了的時候過期，而且一段對一段

1.29.0 讓複習頁可以在原文旁邊開一欄譯文。這份 ADR 寫下三個決定：譯文怎麼跟原文對齊、什麼時候算過期、譯文從哪裡來。前身是一份在 1.24.0 上做的原型，它把三件事都做得比較重，這裡記下為什麼沒有照它走。

我們決定：**以原文的一個區塊（段落、整個清單、引文）為單位，用它自己文字的指紋命名；只有原文改了才算過期；譯文由 agent 在對話裡寫，頁面只負責顯示。**

## Considered Options

- **兩欄各自捲動，用捲動百分比同步**：實作最直接。但兩種語言的長度不成比例，公式與圖表又只在一邊，捲到後半段就對不上了。改成每個譯文區塊跟它的原文排在同一列，兩欄本來就是同一個捲動，沒有東西需要同步。手機上同一份 HTML 讓譯文接在原文下面，同樣不用同步。
- **用「第幾段」命名段落**：簡單，但原文重新轉檔多出一段，後面每一段的名字都換了，整篇譯文一起失效。改用區塊文字的指紋：多一段只影響那一段。原文某段改了，舊譯文對不到任何指紋，就靠前後還對得上的區塊放回原位，標成待更新；放不回去的（同一個縫裡少掉的原文段數和多出的譯文段數不一樣）保留在檔案最後並回報，不擺到可能錯的段落旁邊。
- **術語表或語言偏好改了也算過期**：原型這樣做。問題是一條常用術語可能出現在幾十段裡，改一個字就讓整篇同時變成待更新，那個標記就不再代表「這段跟原文不一致」。過期只看原文；改了術語要不要重譯，由讀者決定，agent 可以替他找出用到舊譯名的段落。
- **在頁面上勾段落、複製任務給 agent、再把 agent 回的 JSON 貼回頁面**：原型這樣做，讓頁面不必開 server 也能發起翻譯。但讀者本來就在 Claude Code 裡讀，在對話裡說「翻譯 S130」就夠了，來回貼兩次只多了出錯的地方。頁面上只剩一顆開關與狀態。
- **譯文的螢光筆另做一套**：原型有自己的色票、註解面板與存檔格式，長得像但行為不同，也進不了「複製畫記」與 `notes/marks/`。改成讓譯文成為同一節裡的第二個畫記區：同一個色票、同一個註解面板、同一個存檔，畫記的 `anchor.file` 指向譯文檔。

## Consequences

- **`notes/translations/<section>.md` 是新的真實來源。** 一節一檔、Markdown，每段前面一行 `<!-- p:指紋 -->`。沒有任何建置會覆寫它；讀者可以直接改字，只是不能動指紋那一行。
- **`translate.py --put` 是唯一的寫入口。** 它擋下公式、引用編號與原文不一致的段落（兩邊用同一套 KaTeX 畫，少一個 `$` 就是一段壞掉的數學），數字對不上只警告。寫檔先寫暫存檔再換上去，失敗不會留下半個檔案。
- **譯文只進複習頁。** `build_html.py` 讀它，`build_annotated.py` 不碰它，所以加譯文只需要重建頁面。
- **參考文獻不算進待翻譯。** 一篇論文五十條書目會讓每一篇看起來都還有三分之一沒翻。
- **術語表與語言偏好在頁面上編輯，但不在頁面上套用。** 「工具 → 譯文設定」透過 server 寫 `TERMS.md` 與 `LANGUAGES.md`，每次寫入都帶著讀到時的版本，別處改過就拒絕，不蓋掉。工具不解析它們來判斷譯文對不對；它們是寫給翻譯的 agent 讀的。
- **譯文沒有自己的版本歷史。** 舊譯文被新譯文取代就沒了；要留就靠 git。原型保留了每一版，但沒有任何介面讀得到它們。
