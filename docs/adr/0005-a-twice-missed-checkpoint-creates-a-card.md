# server 可以新建卡片，但只有段落檢查點連續兩次沒答到時，而且整張卡從固定樣板長出來

ADR 0004 把 server 對 `notes/cards/` 的寫入限定成兩種文字操作：取代 `status:` 與 `updated:` 兩行、在 `## 自己的話` 追加一行。當時的前提是**卡片檔一律由使用者或 agent 建立**，server 只改既有的卡。

1.20.0 的段落檢查點打破這個前提。檢查點問一題，他寫下答案，然後自己判斷答到了沒有；沒答到就換一個說法再問一次，第二次還是沒答到就不再問第三次。此時該發生什麼？「一直問到會為止」正是複習排程在做的事，而那套機制已經存在。所以第二次沒答到的正確結局是**變成一張疑問卡**，交給排程，而不是讓檢查點繼續擋在那一節的結尾。

這件事只能由 server 做。頁面沒有檔案系統；讓 agent 事後補建，等於他讀完一節、發現自己不會、然後要換到對話裡說一次——這條動線在半懂出口（ADR 0004）就被否決過一次，沒有理由在這裡重來。

我們決定：**server 可以新建卡片檔，但僅限「段落檢查點連續兩次沒答到」這一種情形，而且請求裡沒有任何字串會決定檔名、路徑或卡片結構。**

一張這樣的卡由三個既有來源組合而成，全部在 server 端讀取：

1. **編號** 由 `checks.next_card_id()` 掃 `notes/cards/` 產生，檔名由這張卡自己的問題 `marks.slug()` 出來，不是請求給的。
2. **問題與 `## 卡點`** 抄自檢查點檔（`notes/checks/NNNN-*.md`），那是 agent 事先寫好的。
3. **`anchor:`、`tags:`、`## 解答`** 抄自檢查點指名的那則要點（`target: PNNNN`）。卡片因此落在同一句話旁邊，不需要重新定位（ADR 0001）。

只有 `## 自己的話` 來自請求：他兩次寫的答案，逐字追加，日期與「第 N 次」由 server 加。

卡片一律帶 `origin: suggested` 與 `status: open`。`## 解答` 只有要點那一句，並在卡上明說這張卡是檢查點自動建立的、解答還沒展開——下一回合請 agent 補完，或他自己寫。

## Considered Options

- **第二次沒答到就繼續問**：不需要新的寫入權限。但一節的結尾變成一道關卡，而「一直問到會為止」是複習排程的工作，在閱讀動線裡重做一次只會讓人跳過整個功能。
- **只記進紀錄，卡片留給 agent 下次建**：server 完全不碰 `notes/cards/`，最保守。但他讀到一半發現不會，這件事要等到下一次開對話才變成可以複習的東西；中間這段時間頁面上看得到「沒過」卻沒有任何出口。而且「下次記得補」在實際使用上等於不會發生。
- **讓頁面把卡片內容整個送上來，server 照寫**：程式碼最短，也最糟。請求裡的字串會變成檔名、YAML 欄位與錨點，等於把 `notes/` 的寫入介面開給任何能對 loopback 發 POST 的東西。server 的既有紀律（請求字串永遠不變成路徑或命令列）在這裡必須照樣成立。
- **固定樣板，欄位全部由 server 從既有檔案讀出來（採用）**：多幾行程式碼，換來「這張卡的每一個欄位都能指出它抄自哪個檔案」。請求只貢獻他自己寫的那兩句話，而那兩句話本來就會被追加到 `## 自己的話`（ADR 0004 已經允許）。

## Consequences

- **這是 server 唯一會新建 `notes/` 檔案的地方，`notes/marks/` 與 `notes/reviews/` 除外。** 觸發條件單一且可數：`notes/checks/answers/NNNN.md` 裡出現第二筆 `miss`。沒有第二個入口。
- **檢查點的作答紀錄是追加式的，狀態永遠重放、不儲存。** 跟複習紀錄同一條紀律（ADR 0003）。`notes/checks/answers/NNNN.md` 每行一筆 `YYYY-MM-DD verdict [cardid]`，狀態由 `checks.state()` 從整份紀錄算出來，任何地方都不寫入「現在是 pass」這種欄位。
- **頁面烘進去的狀態會過期，所以開著 server 時要重新問一次。** 註記檢視是建置產物：建置之後才作答的檢查點，重新載入會變回沒答過的樣子。頁面啟動時向 `/_pa/checks` 要一次真正的狀態，取代烘進去的那份；沒有 server 就用烘進去的，並且在他當場移動的檢查點上明說這次沒有記錄下來。
- **一張自動建立的卡，解答是不完整的。** `origin: suggested` 就是這個意思，卡上也直說。它會進排程，但在 agent 或他自己補完之前，解答只有要點那一句。
- **建卡之後會重建整篇。** 卡片要出現在註記檢視、`QUESTIONS.md` 與 `catalog.json` 裡，所以 `/_pa/check` 在建卡那一次跑完整個建置，並請頁面重新載入。單純記一筆作答不重建。
- 代價是 `checks.make_card()` 這個樣板函式要跟卡片格式一起維護：卡片欄位改了，這裡不改就會產出過時的卡。
