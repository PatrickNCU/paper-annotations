# 提醒只在有東西到期時出現，而且只說它確實知道的事

1.22.0 把各篇論文到期的卡收成書房頁最上面的一區，但那一區要先打開書房才看得到。1.27.0 讓到期這件事自己找上門：電腦上跳工作列氣泡，頁面標題與分頁圖示帶著張數，手機上有一個每天響的行事曆事件。這份 ADR 寫下這三個出口各自的界線。

我們決定：**提醒只在今天真的有卡到期時出現；說不出確切數字的地方，就直說它說不出來。**

## Considered Options

- **每天固定時間都跳**：實作最簡單。但沒有東西要做的那幾天也會跳，幾次之後讀者學到的是「這個氣泡可以不看」，真正有卡的那天它就被一起忽略了。
- **半懂的卡也算進提醒**：半懂是「還沒寫出自己的話」，是一直掛著的工作，不是到了某天才出現的事。把它算進去，張數就幾乎永遠不是零，提醒於是又變回每天都跳。它留在書房頁的佇列與氣泡的第二句裡，但不決定要不要跳。
- **手機推播（Web Push）**：手機上最像提醒的東西。要 VAPID 的 ES256 簽章與 payload 加密，標準函式庫兩樣都沒有；這個工具不裝任何套件。也不能用「手機會提醒你」包裝一個做不到的承諾。
- **電腦主動把書房頁推到面前**：最不會漏掉。但讀者在做別的事時被一個瀏覽器分頁打斷，比被一個氣泡打斷糟得多；要不要開，是他按下去的那一刻決定的。
- **只在有到期時跳氣泡，點了才開；頁面帶張數；手機用行事曆（採用）**。

## Consequences

- **`remind.py --due` 是唯一的計算。** 氣泡、行事曆的說明文字、以後任何出口都從它來；不開 server 也算得出來，因為它直接讀 `notes/reviews/`，跟書房頁同一份 `srs.today_across`。
- **氣泡由工作排程器每天叫一次，綁在讀者自己的帳號、只在他登入時跑。** 一個沒人在桌前時跳出來的氣泡不是提醒。那個時間電腦沒開，就在下次登入時補跑一次（StartWhenAvailable）。
- **點氣泡或工作列圖示才開書房。** server 已經在跑就直接開頁面，沒在跑就用 `開啟書房.cmd` 起一個。圖示留三十分鐘：回到桌前時還在，不會變成永遠在的家具。
- **標題與分頁圖示只帶「到期」的數字。** 規則跟氣泡一樣；沒有到期時分頁看起來跟以前一模一樣。
- **行事曆事件每天都響，而且說明裡直接寫它不知道今天有幾張。** 數字只有電腦算得出來，日曆檔是靜態的。連結不帶金鑰：行事曆會同步到某家的雲端，而裝好的 app 本來就有 cookie。
- **工作排程器的部分只做了 Windows。** 那是讀者現在用的機器；別的平台等真的有人用再做，不先寫一份沒人跑過的版本。
