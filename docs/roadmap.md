# 接下來要做的事

寫於 1.2.0。這份文件記錄**打算做什麼、為什麼是這個順序**，不是規格書；每項的細節在動工時才定案，重大的結構決定另外寫成 ADR。做完一項就把它從主線移到「已完成」並註明版本。

## 現況（1.2.0）

單篇論文的循環已經完整：提問 → 疑問卡掛回原文 → Markdown 檢視與單頁複習頁 → 螢光筆畫記存檔 → 原文換版本後 `reanchor.py` 救援 → 匯出 Anki／CSV／JSON。

缺的全部在「一篇論文」這個邊界之外，加上一個邊界之內的洞：**系統的視野等於使用者的困惑**——他讀懂的東西不留痕跡，而跨論文的關係恰恰長在那裡。

## 已完成

- **0／1／2 於 1.3.0**：登記簿、卡片目錄、參考文獻比對、要點、接線 digest。細節見下方各項的
  原始規劃；實作與規劃的差異只有一處，記在第 1 項裡。

## 主線

### 0. 論文登記簿、卡片目錄、參考文獻比對 ✅ 1.3.0

**目的**：讓 agent 在開新論文的第一時間就知道使用者讀過什麼。今天做不到——每個工作區彼此不認識，新 session 對舊論文毫無線索。這是所有跨論文功能的前置。

**範圍**

- `papers.yml` 放在 git repo 根目錄（使用者已拍板：跟著 git 走，跨機器靠既有的 git 同步）。指令從論文目錄往上走去找它，跟 git 找 `.git` 同一招。內容極小且可手改：每篇一行的路徑、標題、Tier。`probe.py` 首次探測一篇論文時自動登記。
- `notes/catalog.json` 由 `build_annotated.py` 產生，一篇一份：每張卡與每則要點的 id、標題、tags、狀態、一句話。跨論文的讀取者掃這個，不必去讀幾十個 Markdown——卡片數長大後才不會爆。生成物，可重生。
- `probe.py` 抽出參考文獻清單存成 `notes/references.json`（機械、與登記簿無關、不會過期）。**比對留到讀取時才做**，這樣新增一篇論文，舊論文的引用關係自動跟著更新。

**為什麼排第一**：最便宜，而且 0–2 三項合起來才構成使用者要的「串聯」。參考文獻比對更是完全不需要判斷的免費跨論文邊——「RePlAce 引用了你讀過的 ePlace-MS」是機械可驗證的事實，而引用當下那句話（「我們沿用 [12] 的靜電模型，但把…換掉」）往往就是最高品質的關係描述。

**風險**：登記簿裡的路徑會因為使用者搬資料夾而失效。失效的項目要明說，不要靜默跳過——與 ADR 0001 同一種態度。

**第一步**：定 `papers.yml` 與 `catalog.json` 的格式，`probe.py` 寫入登記簿。

### 1. 要點（第三種筆記類型）✅ 1.3.0

**目的**：記錄論文骨架——主張、方法、假設、定義、結果、限制。這些是跨論文比較的單位。設計決定見 [ADR 0002](adr/0002-points-are-a-third-note-type.md)。

**範圍**

- `notes/points/NNNN-slug.md`，frontmatter 帶 `kind`、`origin`、`tags` 與跟畫記相同的 `anchor` 區塊，內文一句話。共用 `pa/anchors.py` 與複習頁的渲染管線。
- 取得規則寫進 `SKILL.md`，兩條並用：
  - **開卷一次**：`probe.py` 之後做一趟結構化掃描——摘要、引言、結論、各節標題、明確標了貢獻的段落。不讀全文，成本有界，但論文的主張本來就寫在這幾個地方。
  - **順手記**：之後每次為了回答問題讀某個 chunk，同時記下該 chunk 裡值得留的要點。零額外閱讀成本。
- 護欄：每回合結尾列出新增的要點供當場否決；開卷掃描有數量上限；`origin: agent` 的在複習頁上比使用者自己的安靜，可一鍵隱藏。

**刻意不做**：不做全文精讀式的要點抽取。覆蓋率換成本划不來，而且會壓垮信噪比。

**風險**：信噪比。見 ADR 0002 的 Consequences。

**實作時改的一件事**：要點**只用引文定位**，不爬卡片的 `ref → heading → quote` 階梯。
規劃時沒想到——卡片講的是論證裡的一個位置，退到小節開頭仍然成立；要點轉述的是特定那一句，
掛到半頁之外就變成對錯誤的文字說錯誤的話。`heading` 因此降為純標籤，記進
`references/anchoring.md`。

### 2. 「接線」digest 模式 ✅ 1.3.0

**目的**：使用者開始讀新論文、或讀完一輪時，產出與已讀論文的關係。

**範圍**：`references/digests.md` 新增第四種模式 `connections`，輸出三類、逐條附出處（沿用既有的 digest 規矩）：

- **關聯**：這篇的哪一段對應到哪篇的哪張卡／哪則要點
- **共識**：兩篇主張同一件事但講法不同——往往正是使用者重複卡住的原因
- **矛盾**：兩篇說法對不上。最有價值的一類，通常代表領域裡有真正的爭議，或使用者誤讀了其中一篇

**工作量幾乎為零**：這是 agent 撰寫的整理，不是腳本。0 和 1 把資料準備好之後，這一項只是文件工作。

**現成的例子**（寫作時工作區裡就有）：RePlAce `0002-preconditioner-vs-local-density` 與 ePlace-MS `0003-why-macros-oscillate-without-preconditioner` 顯然在講同一件事的兩面；RePlAce `0001-what-replace-changed-over-eplace` 整張卡就是一個跨論文關係，現在只能寫成散文塞在卡片正文裡，從 ePlace-MS 那一側完全看不到。

### 3. 內建間隔重複 ✅ 1.5.0

**目的**：複習動線由工具自己負責。Anki 匯出降為「想用的人可以用」的附加選項，不再是這項功能的實作方式。

**這一項會改變系統的地基**：複習歷史是**第一份不可重生的資料**。今天卡片＋畫記＋原文可以重建出每一個位元組；「我哪天複習過、當時答得如何」推導不出來，弄丟就是沒了。動工前先寫 ADR 0003，把儲存位置、與 build 的互動、`reanchor.py` 換版本時怎麼跟著卡片走定死。

**範圍**：新增 `pa/srs.py` 與 `notes/reviews/`；複習頁側欄多一個「今天要複習」；評分經 server 寫回，沿用畫記那條已驗證的路徑（同一個 token、同一個 rebuild 子行程）。演算法用 **SM-2 簡化版**（約 40 行、無參數擬合）。FSRS 更準，但要 17–21 個參數與一支 optimizer，在零相依前提下不划算。

**已拍板的三件事**

- **排程對象**：`resolved` 進正常排程（已經懂了，現在要記住）；`half` 進不排程的「待攻克」佇列，永遠優先顯示；`open` 不進；`origin: suggested` 預設不進。
- **離線評分不做**。SRS 必須跑 server。理由是複習歷史不可重生，而 localStorage 是使用者清一次瀏覽器資料就沒有的地方——畫記丟了還能重畫，複習排程丟了無法重建。沒跑 server 時「今天要複習」要明說功能未啟用，不要假裝能用。
- **要點的 `kind` 清單**維持六種：`claim / method / assumption / definition / result / limitation`。

**刻意不做**：不做 FSRS，不做複習統計圖表，不做離線評分。

### 4. 書房頁與多論文 server ✅ 1.6.0

**目的**：一個統一介面切換不同論文的筆記，並聚合第 3 項的到期張數（「今天全部 12 張：ePlace-MS 7、RePlAce 5」）。

**必須正面處理的安全問題**：現在 `pa/server.py` 的 root 是 `commonpath(annotated, paper_root)`，安全性靠 stdlib handler「不會走到 root 以上」。多篇論文散在硬碟各處時 commonpath 會一路退到 `C:\`——等於把整顆碟掛上 localhost。**不要合併 root**：每篇論文一個掛載前綴（`/p/<slug>/…`），各自在自己的 root 內解析；存畫記的請求帶**論文代號**，由 server 端的登記簿查出路徑，維持「路徑絕不取自請求」這條紅線。

**不受影響**：`--embed-assets` 的單檔分享頁維持單篇。

**1.7.1 補的兩個洞**：書房沒有啟動器（`--launcher` 只認單篇模式），以及從磁碟雙擊開啟時
論文連結全斷卻只在頁尾用小字解釋——事後解釋等於沒解釋，改成偵測到非 http 就在最上面明講。
順帶決定了一件事：**不做「點擊時才啟動該論文的 server」**。那需要網頁能生出 process，
權限遠大於讀檔案，會讓前面為了不讓整顆磁碟曝光所做的限制失去意義。

### 5. 卡片之間的型別連結與反向連結 ✅ 1.7.0

**實作時改的兩件事**：連結寫成一行字串（`contradicts eplace-ms#P0003`）而不是 type/to 的
對應——miniyaml 不支援 mapping 的序列，而這件事不值得為它擴充格式。另外跨論文的目標**不做
超連結**：對方論文在自己的 root 底下，磁碟上與 server 上的路徑不同，一個 href 只能在其中
一邊是對的。改成把目標那一句話直接顯示出來，反正那才是想看的東西。日後多論文 server 成熟
了可以補上 `/p/<代號>/` 的連結。

**目的**：把第 2 項產生的洞見固化成結構。digest 是散文，適合思考、不適合查詢；連結是結構，適合累積、但要先有洞見才寫得出來。兩者是前後關係，不是二選一。

**範圍**：連結存在卡片 YAML（單向宣告），build 時解析並在兩端渲染反向連結——存一份、雙向顯示，不會漂移。型別至少要能表達 `answers`（這題的答案在那篇）、`contradicts`（說法矛盾）、`same-as`（同一概念不同講法）。解析遵循 ADR 0001：目標不在登記簿裡就標成未解析，不猜。

**為什麼排在第 2 項後面很久**：先用 digest 跑幾輪、知道哪些連結真的值得固化，再定型別清單。反過來先定格式很容易定歪。

### 6. 觸控與手寫

使用者指定排最後，但設計要先想清楚，免得前面的資料格式沒留空間。

**觸控**：現有互動全建立在 `mousedown`/`mouseup` 與 `getSelection()` 上（含 1.2.0 修好的「公式一次點擊」）。iPad Safari 上會踩到長按選單、選取控制點、沒有 hover，還有 24px 的刪除鈕遠低於 44px 的可觸控下限。改用 Pointer Events，並以 `pointerType` 區分手指捲動／筆畫線。

**手寫的錨定**——核心難題是正文會重排，絕對頁面座標必定錯位。評估過四種：

| 做法 | 判斷 |
|---|---|
| 絕對頁面座標 | 改視窗寬度就全歪。淘汰 |
| 綁區塊＋座標對區塊寬度正規化 | 橫向對得上，換行數一變縱向會拉伸。圈選、打勾、箭頭堪用，貼著字的底線會歪 |
| 綁文字錨點（複用畫記的 quote 解析） | 只適合「這句話旁邊一個記號」，撐不住自由筆跡 |
| **邊欄畫布（採用為 MVP）** | 筆跡畫在正文旁的固定寬度欄位，錨在段落起點。紙本閱讀時手寫本來就多半在頁邊空白；重排只要跟著段落走，不必跟字對齊，對 KaTeX 行內公式完全免疫 |

**儲存**：`notes/ink/NNNN-slug.md`，frontmatter 用現有錨點機制錨到區塊，內文放筆跡的 path 資料（含 pointer events 給的壓力，有就存、沒有不要求）。**Python 端只收下並存檔，不解讀內容**——零相依因此成立。

**歸類**：比照畫記——不是卡片、不進疑問統計。

**不做手寫辨識**：零相依做不到，接雲端 API 又違背離線可開。替代方案是每筆筆跡可以打一行字當標題，可搜尋的部分靠它。

## 明確不做

- **引用關係圖視覺化**（Connected Papers 那種）：好看大於好用。第 0 項的參考文獻比對已經給出實際價值。
- **手寫辨識**：見上。
- **協作／多使用者**：這套工具服務一個讀者。
- **AI 全文摘要**：`references/digests.md` 的拒絕理由依然成立——工具唯一獨有的資料是使用者自己的卡片，摘要任何通用工具都做得更好。
- **內建 PDF 閱讀器**：輸入形狀就是轉檔後的 Markdown，見 `references/tiers.md`。
- **FSRS**：見第 3 項。

## 已經拍板的決定

- 登記簿放 git repo，跟著版控走，不放使用者家目錄。
- 間隔重複內建，Anki 匯出是附加選項而非實作方式。
- SRS 必須跑 server，不做離線評分；排程對象 `resolved` 進、`half` 另立佇列、`open` 與 `suggested` 不進。
- 要點的 `kind` 固定六種。
- 平板要支援，但排在最後。
- 要點是第三種筆記類型（ADR 0002）。
- 複習模式分段揭示，卡點藏到最後；閱讀模式不給評分列（第 8 項）。
- 評完不自動跳下一張，按「下一張」。
- 卡片有 `## 自己的話`，agent 不在裡面寫散文；一句話直覺可由讀者寫（`intuition: user`）。
- 半懂卡的出口是讀者自己解釋再比對，沒有評分列。
- server 可以寫 `notes/cards/`，但只能取代 `status:`／`updated:` 兩行、在 `## 自己的話` 追加，
  不經 `miniyaml.dump`（ADR 0004）。agent 改狀態時守同一條。
- 一回合最多 5 張卡變 `resolved`；其餘留 `half` 回頁面。
- agent 回合結尾提議本機 `git commit`，從不 push，從不替他建 GitHub repo。
- 文獻回顧只做「他寫、工具核對」（整理的第五種模式 主張核對），不替他寫。
- 回合暖身題只能從要點出，不能從卡片出——卡片的複習只在頁面上、只在有紀錄的地方發生。
- 「這張你累計複習 N 次」是 agent 唯一允許說的複習統計句；沒有連續天數、沒有分數、沒有圖。
- 平板的過渡方案是任何能同步資料夾的 Markdown 應用（Obsidian 也算）唯讀加草稿；複習與評分
  留在電腦上。筆記不搬進 vault。

### 7. 書房頁的分類 ✅ 1.8.0

分類存在 `papers.yml`：`topics:` 是詞彙表（先定義才能用），每篇底下 `topics`（使用者的）／
`topics_auto`（AI 建議的，一樣生效）／`topics_off`（移除過的，不得再建議）。書房頁是一份
清單加一排篩選標籤，一篇論文只出現一次、它的分類都顯示在自己的卡片上。編輯與自訂分類都
需要 `serve.py --library`。提議分類的時機是 `/paper-annotations:setup`。

**一開始做錯的一件事**：把「多個分類都顯示」讀成「論文重複出現在每個分類區塊」，實際上
使用者要的是「卡片上顯示它的所有分類」。前者在 50 篇 × 3 分類時會變成 150 張卡要捲。

**兩個當初沒想清楚、實作時才定案的點**

- **「build 時分類」和「由 AI 想分類」互相衝突**：build 是純 Python 且必須冪等，裡面沒有
  LLM。拆成「對話中提議並寫進登記簿」與「build 只讀取分組」兩段才成立。
- **關鍵字不能直接當分類**：實測 ePlace-MS 與 RePlAce（一篇是另一篇的直接後繼）13 個
  Index Terms 交集為零，每篇各自成一類等於沒分類。關鍵字降為建議的原料，抽進
  `catalog.json` 的 `keywords`。

順手修掉一個資料遺失：`save_registry` 原本每次都蓋回罐頭標頭，使用者手寫在 `papers.yml`
的註解會在他按下書房頁任何一顆按鈕時消失。改成保留檔案原有的開頭註解區塊。

### 8. 複習動線：分段揭示、讀者的話、半懂的出口 ✅ 1.17.0

寫於 1.16.0，1.17.0 一次做完（原本排的六步沒有分版，因為每一步的頁面改動都在同一個
`page.js` 模組裡，拆開反而要改三次）。起點是兩個事實：論文筆記登記兩週後 0 張疑問卡、`notes/reviews/` 還不存在；
而現在的複習面板一開就整張攤開（`annotate.py` 把卡點／解答／直覺當兄弟區塊，`openCard`
全搬進面板），每次複習等於重讀。先用假資料做了一個可點的試玩
（[prototypes/review-flow-demo.html](prototypes/review-flow-demo.html)，雙擊可開），使用者
玩過後全部同意，以下是試玩驗證過的決定。

**目的**：讓提取真的發生在看答案之前；讓讀者自己的話留在卡片裡；讓半懂卡有出口；讓
「今天有卡到期」出現在讀者真的會看到的地方。

**複習模式**（從複習清單或 `#card-NNNN` 進入）分四段：

1. 問題＋原文那句話。卡點、解答、直覺都藏著。
2. 先答把握：想得起來／模糊／想不起來，綠／黃／紅，與狀態點同一組色。按下去才看得到直覺。
3. 一句話直覺＋評分列——這時就能評分。有跨論文連結的卡在這裡插對照題：一行「先想：對方對
   同一件事怎麼做？」，對方那句話收在 `<details>另一篇怎麼說？</details>` 裡。要放在解答
   之前，因為解答本身通常就寫了另一篇怎麼做。
4. 「看完整解答」才攤開卡點＋解答＋自己的話。**卡點藏到最後**：SKILL 把它定義成「缺的
   前提」，通常就是答案。

- 評完**不自動跳**下一張，改成按「下一張」，佇列空了按鈕變「今天做完了，關閉」。推翻
  `page.js` 目前的自動跳：把握對不上的那句話（「你說想得起來，結果按了重來」）是這條動線的
  重點，自動跳會讓它一閃就沒。
- 把握對不上只在兩種情況說一句：想得起來→重來；想不起來→良好／簡單。其他不說。

**閱讀模式**（從正文反白句或疑問清單進入）：整張攤開，跟現在一樣，但**不給評分列**——
看過解答再評分就是重讀分數。到期的卡只給一顆「這題今天到期 · 用複習模式作答」。半懂卡在
閱讀模式也不攤開，一律走下面那條路。

**半懂卡的出口**：清單顯示「半懂 N 天」（從 `updated` 算）。打開只給問題＋卡點＋一個
「用自己的話說一次」的框；按「比對解答」才看到解答與直覺；然後由讀者按「對上了：懂了，
進排程」或「還是半懂」。兩者都把他寫的那句存進卡片；「懂了」把 `status` 改成 `resolved`、
`updated` 換成今天，當天就到期。沒有評分列——半懂不是記憶問題。

**讀者的話**

- 卡片第五個選填段 `## 自己的話`，一行一筆，帶日期與種類：`2026-08-28 猜：…`／
  `2026-09-02 解釋：…`／`2026-09-02 半懂：…`。**agent 永遠不在這一段寫散文**；他的原話
  逐字保留，不套 Language 那條「一種形式」的規則。
- 對「為什麼／怎麼會」類的機制問題，agent 先問一句「你先猜猜看，一句就好，猜錯沒關係」；
  他說「直接講」就跳過，該回合不再問。猜的話進 `自己的話`。
- 回合結尾問「用一句話說，這題的直覺是什麼」；他答就取代 agent 的直覺，frontmatter
  `intuition: user`，頁面上直覺旁標「你寫的」／「AI 寫的」。

**當天重來**：最後一筆是今天的 `again` 的卡留在今天佇列最後，標「再答一次」；同一天第三次
`again` 就放下，清單下面說「今天先放下，明天再來」。重來鈕的預覽字是「等一下再答」，第三次
是「今天先放下」。純重放層的改動，紀錄格式不動。

**複習區永遠在**

- 開場一行「今天到期 N 張 · 半懂 M 張 · 下一張 MM-DD」；`library.py` 每次即時重放所有登記
  論文的 `notes/reviews/` 印同一行；SKILL 第 0 步先報這個，第 6 步收尾說「今天解決的 K 張
  明天第一次回來」。
- 三種空狀態：還沒有排程中的卡（先讀、先問）／今天沒有到期的卡 · 下一張 MM-DD＋「提前
  複習一張」／今天做完了，明天 N 張。半懂卡永遠列在最上面，空狀態只看到期的那部分。
- 「提前複習一張」開最早到期的那張；server 已允許提前評分，不用改。提前複習不算「今天
  做完了」。
- 標題的計數是到期數，不含半懂。
- `page.js` 處理 `#card-NNNN` 與 `#review`，對話裡的複習給一個點了就開到那張卡的連結。

**紀錄格式**：把握跟評分一起寫，`2026-09-02 good sure`（`sure|vague|blank`，選填第三欄）。
讀取端與寫入端同一版放寬（1.17.0）；舊版 plugin 讀新紀錄會整行丟掉，接受，寫進 ADR 0003
的補記。

**對過 `srs.py` 的兩個假設**（試玩時猜錯一個）：重來之後**不**回到首次間隔表——`again`
把間隔設成 1 天、ease 減 0.2，下一次良好是 round(1 × ease)，約 2 天，不是試玩的 1 天。
實作保留原演算法，只把首次間隔改成 困難 1／良好 2／簡單 4，讓第一次複習的三顆鈕不再
承諾同一天。取整用 Python 的 `round()`（.5 取偶數），和試玩的 `Math.round` 在 .5 時可能差
一天，接受。

**刻意不做**：FSRS、複習統計、離線評分，維持第 3 項。

**落地的樣子**：`srs.schedule` 多了 `since`／`retry`／`parked`／`next`／`tomorrow`／
`done_today`，佇列順序是半懂（等最久的在前）→ 到期 → 當天重來；`page.py` 永遠輸出複習區；
`annotate.py` 渲染 `## 自己的話` 與「你寫的／AI 寫的」標記，跨論文連結先問後答；
`notes.set_card_status`／`append_self_line` 是 server 與 agent 改卡片的唯一兩個入口
（ADR 0004）；`POST /_pa/card` 關半懂卡；`POST /_pa/review` 收第三欄並回「對不上」那句話；
`page.js` 的三種模式（閱讀／複習／半懂）全靠面板的 `data-stage` 讓樣式表藏區塊，卡片的
HTML 不拆；`library.py` 第一行印即時重放的到期行，`--due` 只印那一行。SKILL、review、setup、
digests、README 一起改。

**成功標準**（一個月後對這幾個數字，不達標就是動線沒被用，回到這一項重看，不是再加功能）：
`notes/reviews/` 存在，且至少一張卡有三筆以上紀錄；至少一張半懂卡是從頁面關掉的（卡片裡
有 `解釋：` 行）；`猜：` 行出現在至少三張卡；紀錄裡出現過 `again sure`——代表把握度真的
在量東西，而不是每次都按模糊。

**風險**：server 開始寫使用者手寫的卡片檔（ADR 0004 把改法限死在兩行取代加檔尾追加）；
卡片被外部編輯器動過時 text-replace 的假設要成立（`status:` 必須在行首、frontmatter 用
`---` 圍住——`load_cards` 本來就這樣要求）。
