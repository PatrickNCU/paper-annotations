# paper-annotations

讀論文時把疑問就地註記回原文，累積成可複習的筆記與單頁 HTML；順手畫的螢光筆與註解也一起收進來。

- 論文原文唯讀，`notes/` 是唯一真實來源，註記檢視與複習頁可隨時重新生成
- 疑問掛在公式編號、圖、表、小節或指定的一句原文上；每次建置都對實際內容重新解析
- 產出單頁 HTML：側邊目錄、疑問清單、狀態篩選、全文搜尋、明暗主題，公式離線渲染
- 卡住的那句原文會標成高亮，卡片被篩掉時高亮跟著收起來
- 讀的時候可以畫螢光筆（四色）、在畫記上寫註解，按「存檔」就直接進筆記資料夾
- **內建間隔重複**：懂了的卡自動排程，到期時回來找你；半懂的永遠排在最前面。
  紀錄是純文字、追加式，排程由重放算出，換演算法不必遷移
- 正文裡的「見 Fig. 4」「Algorithm 2」可以點著跳；演算法自成色塊
- **讀第二篇開始有用**：登記讀過的每一篇，比對參考文獻找出誰引用誰，把新論文接回舊筆記；
  書房頁一眼看完全部論文的疑問與今天要複習幾張
- **今天要複習在書房頁上就做得完**：所有論文今天到期的卡收成一列佇列，直接在那裡作答評分，
  不必一篇一篇打開去找
- **書房頁可以分類**：一排標籤篩選，一篇可屬於多個主題。分類由 AI 在設定論文時建議、
  你隨時增刪，也可以自訂像「已讀過」這種自己的分類；看得出哪些是你定的、哪些是它猜的
- **要點**記下論文自己的主張、方法、假設，補上「你沒卡住所以什麼都沒留下」的洞——
  兩篇論文的矛盾長在主張上，不在誰的疑問上
- **有型別的連結**（回答／牴觸／同一件事）：寫一邊，兩邊都看得到。整理要你想起來去翻，
  連結會自己出現在它所談的那一句旁邊
- 可以把累積的疑問整理成回顧單、主題聚合、前提盤點，或跨論文的接線——輸出是公式已渲染
  的網頁，不必裝 Markdown 編輯器就讀得了；卡片也能匯出到 Anki
- 零依賴，只需要 Python 3.8+

## 跟其他工具的差別

| 類別 | 代表 | 它記什麼 |
|---|---|---|
| PDF 標註／文獻管理 | [Zotero](https://www.zotero.org)、[Obsidian Annotator](https://github.com/elias-sundqvist/obsidian-annotator)、[PDF++](https://github.com/RyotaUshio/obsidian-pdf-plus) | 螢光筆與註解——「這段很重要」 |
| Web 標註 | [Hypothes.is](https://web.hypothes.is) | 引文定位的公開標註層 |
| AI 讀論文 | [SciSpace Copilot](https://scispace.com)、ChatPDF、Explainpaper | 對話與摘要，存在側邊筆記本 |
| 間隔複習 | [RemNote](https://www.remnote.com)、[SuperMemo](https://help.supermemo.org/wiki/Incremental_reading) | 抽出原文做成卡片，有排程演算法 |
| Agent plugin | [research-papers-plugin](https://github.com/ctoth/research-papers-plugin)、[phd-skills](https://github.com/fcakyon/phd-skills) | 把論文加工成結構化摘要與 claims |

這套工具記的是**你的問題**。點開才有答案——複習時你得先自己答一次。上面每一類都不記
這個：它們記重點、記答案、記摘要，就是不記讀的人哪裡不懂。

螢光筆與註解這裡也有（見〈複習頁〉），但它們是配角：**問題才是這份筆記的組織原則**，
畫記不進疑問清單、不算狀態。

三個實際差異：

- **問問題本身就是記錄動作。** 不必停下來切到標註軟體再手動建卡。incremental
  reading 這類方法通常死在這道摩擦上。
- **錨點是每次建置重新解析出來的，不是宣告的。** 先試公式編號這種重新轉檔後仍然
  存在的標籤，再試小節標題，最後才用引文；比對到多個位置就拒絕猜並報錯。
  Hypothes.is 的[研究](https://www.arxiv.org/abs/1512.06195)量測過純引文定位的下場：
  27% 的標註已經失去依附，另外 61% 只要內容一改就會失去。
- **卡片就是你當初卡住的那一句。** 引文會在複習頁上標成高亮，不必重讀整段才想起
  自己在問什麼。
- **產物是純檔案，而且出得去。** 卡片是 Markdown，可以進 git；複習頁是一個離線
  HTML，沒有帳號、沒有訂閱、沒有廠商。複習排程內建，紀錄也是純文字；真要搬去
  Anki，`export_cards.py` 可以把卡片連同複習狀態倒成 Anki 匯入檔（公式自動轉成
  Anki 的 MathJax 寫法）、CSV 或 JSON。

**不適合的情況**：想直接標 PDF 不想轉檔（用 Zotero；開源轉檔工具不少很吃硬體，
沒有 GPU 加速時可能比用 LLM 轉還慢）、要標圖上的區域、要多人共享標註層（用
Hypothes.is）、要管理整個文獻庫（用 Zotero）。

## 安裝

需要 Claude Code CLI（`/plugin` 是互動面板，桌面版叫不出來）。在 CLI 裡跑：

```
/plugin marketplace add PatrickNCU/paper-annotations
/plugin install paper-annotations@patrickncu
```

安裝範圍選 **user scope**，這樣在任何資料夾都能用。零依賴，只要有 Python 3.8+。

## 開發

安裝會把 plugin 複製到 `~/.claude/plugins/cache/`，那才是 Claude Code 實際載入的副本。
要改功能請改這個 repo，push 之後在面板上 **Update marketplace** 再重裝；直接改 cache
會在下次更新時被覆蓋。

本機開發可以直接把 clone 下來的資料夾當 marketplace：
`/plugin marketplace add <你的 clone 路徑>`

## 先把 PDF 轉成 Markdown

這套工具吃的是 Markdown，不是 PDF。repo 裡附了一份轉檔規則文件：
**[skills/paper-annotations/references/pdf2md_rules.md](skills/paper-annotations/references/pdf2md_rules.md)**（v1.4，968 行）。
它是寫給 LLM 看的規格書，管到逐字保留、多欄閱讀順序、圖說對應、表格、公式、
Algorithm 縮排，把正文切分成 `sections/` 並產生索引，以及套件資料夾要叫什麼名字。

用法是開 **ChatGPT 網頁版**，同時上傳這兩個檔案：

1. `pdf2md_rules.md`
2. 你的論文 PDF

然後貼上規則文件 §0 裡的那段指令（開頭是「請依照本文件處理上傳的 PDF」），
把回傳的 ZIP 解壓到論文資料夾即可。

為什麼是 ChatGPT 網頁版而不是現成的 pdf2md 工具：聊天額度限制幾乎可忽略，AI 轉檔
可以做更積極的篩選（頁碼、頁首頁尾這類版面雜訊會被丟掉，不會混進正文），而且不少
開源轉檔工具相當吃硬體——沒有 GPU 加速時，實測轉一篇論文比丟給 LLM 還久。

兩個要有心理準備的地方：

- **很花時間。** 一篇 IEEE 期刊論文通常要多次來回。
- **模型與推理強度顯著影響結果。** 實測 GPT-5.6 Sol＋高推理較佳。

想用自己的工具轉也可以，只要 Markdown 有章節標題就能用——只是疑問沒辦法精準掛在
公式或圖表上，論文改版時比較容易對不上位置。轉完跑 `/paper-annotations:setup`，
它會告訴你這份轉檔支援到什麼程度。

## 產物放在哪

```
論文資料夾/
  論文.pdf
  開啟複習頁.cmd        ← 點兩下就開（setup 時產生）
  論文_md/              ← 轉檔套件（原文唯讀）
    sections/ INDEX.md images/
    notes/              ← 你的筆記，唯一真實來源
      cards/            ← 疑問卡
      marks/            ← 螢光筆畫記與註解
      digests/          ← 整理（額外產物）
  annotated/index.html  ← 複習頁，跟套件同一層
```

筆記跟原文放在一起，整包搬走還是完整的；複習頁放在套件外面，不用在幾十個檔案裡
翻。想換位置在 setup 時說一聲就好（`--out` 移動筆記、`--review` 移動複習頁），
路徑會記進 `notes/paper.yml`，之後都不必再帶。

## 手改筆記

`notes/` 是唯一真實來源，手改是預期用法。平常是 agent 直接寫這些檔案（沒有產生器腳本，
格式規則寫在 skill 裡），你自己改完全一樣。資料流是單向的：

```
sections/（原文，唯讀）┐
                       ├─► build_annotated.py ─► annotated/*.md ─┐
notes/cards/*.md      ─┘                                        ├─► build_html.py ─► index.html
notes/marks/*.md ───────────────────────────────────────────────┘
```

所以**只有 `notes/` 底下值得改**，而且改了**一定會**反映到複習頁——重建之後。
`annotated/` 與 `index.html` 是衍生檔，每次建置整份重生：在那裡改東西，下一次
`/paper-annotations:build` 就沒了。那些檔案開頭都有 `GENERATED by paper-annotations`，
看到就別動。

### 疑問卡 `notes/cards/`

一張卡一個檔 `notes/cards/NNNN-slug.md`，上半是 `---` 包住的 YAML，下半是四個 `##` 區塊。

**可以放心改**：`## 問題`／`## 卡點`／`## 解答`／`## 一句話直覺` 的內文（Markdown、
`$公式$`、清單都照常渲染，少寫某一區塊只是那個色塊不出現）、`tags`、`status`、`updated`。
改 `status` 會連動側欄圓點、篩選與匯出（預設不匯出 `open`）。

**四個要小心的**：

| 欄位 | 改壞的後果 |
|---|---|
| `anchor.quote.exact` | 必須跟原文逐字一致、且全篇唯一。對不上就退回 `ref`／`heading` 定位，都沒有就成為未錨定，**而且反白會消失**——引文不唯一時一律拒絕標記。含公式、程式碼或連結的句子掛得上但不會反白，建置時列在「沒有反白的疑問」 |
| `status` / `origin` | 值是固定的（`open`／`half`／`resolved`、`asked`／`suggested`），打錯會被擋下 |
| `id` | 不能跟別張撞號。改檔名不影響 id，以 YAML 裡的為準 |
| `---` 分隔線 | 整塊 YAML 讀不到的話，這張卡**完全不會被使用** |

改完跑 `/paper-annotations:build`。

**後果是吵，不是靜默。** 上面每一種都會在建置訊息裡點名到檔案：YAML 壞掉會講「這張卡沒有
被使用」，`## 問題` 空白會講，撞號會講跟誰撞，「引文找不到」與「引文出現多次」會分開講，
因為修法相反。最壞的情況是一串警告，不是筆記悄悄消失。

### 畫記 `notes/marks/`

螢光筆畫記也是一檔一條，frontmatter 跟卡片同一套，**內文就是註解**：

```yaml
---
id: "0003"
created: 2026-08-16
color: yellow | green | blue | red
anchor:
  file: sections/S210-....md
  quote:
    prefix: |-
    exact: |-
    suffix: |-
---

註解內文，沒有就整段留空
```

`color` 換顏色、內文換註解、整個檔刪掉就是刪畫記，改完重建。開著 server 的話這些在
頁面上直接做就行，不必開檔案。

畫記**沒有 `status`、不進疑問清單、不算進「疑問 N 則」**——只是把一段標起來加一句話時
用它，真的有一個需要回答的問題才建卡。這條界線是刻意的：混在一起，「疑問 N 則」這個
整個複習頁賴以組織的數字就失去意義了。

## 讀的時候：起一個本機 server

平常讀論文就用這個：

```bash
python serve.py <論文路徑>
```

平常不必自己打這行：`/paper-annotations:setup` 會在論文資料夾裡放一個**點兩下就能開**的
啟動器（Windows `開啟複習頁.cmd`，其他系統 `.command`），書房則是 `開啟書房.cmd`。
那個視窗就是 server，關掉它就停。

差別只有一個：從這條網址開的複習頁多一顆「💾 存檔」，畫記按下去直接寫進 `notes/marks/`
並重建；已落檔的畫記也能就地換顏色、改註解、刪掉。**其餘功能完全相同。**

「server」跟網際網路無關——預設只在 `127.0.0.1`（你這台自己）上聽，封包不離開電腦，
**離線一樣能用**。同網段的人連不到，實測從本機 LAN 位址連是被拒絕的。其他防線：寫入
只限 `notes/marks/`，檔名一律由 server 產生，請求裡指定的章節必須是這篇論文已宣告的；
存檔要帶啟動時產生的 token，而且檢查 `Origin`——瀏覽器裡別的網頁既讀不到 token
（不送任何 CORS 標頭），也送不出那個自訂標頭。

要讓手機也連得到，得自己加 `--host`，見下一節——那一步是刻意的，不是預設。

一個 server 對一篇論文：換論文就換參數，要同時開就換 `--port`。

**沒有 server 也完全能讀**，只是那顆存檔鍵不會出現（它靠探測後端決定要不要顯示），
畫記留在瀏覽器裡，要落檔就按側欄的「複製畫記」貼回對話，agent 會用 `import_marks.py`
寫進 `notes/marks/`。這條路是留給**收到檔案的人**的——見下面〈寄給別人〉。

**畫記不會跨著 `file://` 和 `http://` 走**：瀏覽器把這兩者當成不同來源，各有各的
localStorage。改用 server 之後就固定從 `http://127.0.0.1:…` 讀；先前直接開檔案時畫、
還沒落檔的畫記，要先在原本那個分頁按「複製畫記」帶出來。

## 書房頁的「今天要複習」

書房頁最上面是今天該做的事：**每篇論文到期的卡合成同一列佇列**，順序跟複習頁側欄同一條
規則——半懂的永遠在最前面（等最久的先），再來是到期的（到期日早的先），今天答錯要再答
一次的排最後。標題旁邊的數字是今天到期幾張，底下一行是「到期 N 張 · 半懂 M 張 ·
下一張 X」，再底下把它拆成每篇論文一顆，點了進那篇論文。

點佇列裡的任何一張，卡片就在同一頁展開，**分段揭示與評分跟複習頁完全一樣**——因為那一段
流程是同一份程式，兩邊不會各自漂移。差別只有卡片從哪裡來：複習頁上卡片本來就在頁面裡，
書房頁則是點下去才去跟 server 要那一張（一次一張，不會把今天所有答案先送到瀏覽器）。
卡片右上角的「去原文」跳回那篇論文的複習頁，開在同一張卡上。

一天超過 60 張時只發前 60 張，並明說還有幾張排在後面——做完會再出現。

**整個區塊可以收起來**：點標題就收合，只留標題與底下那一行「到期 N 張 · 半懂 M 張」，
佇列與卡片收起來。收或開記在瀏覽器裡，下次開還是你留下的樣子——不會每天早上重新展開
一次讓你再關一次。收著的時候數字照樣在，因為那正是這個區塊擺在最上面的理由。

這一段要 server 在跑（`開啟書房.cmd`）：複習紀錄要寫成檔案，頁面自己寫不了。直接從磁碟
開 `library.html` 時這個區塊不會出現，因為它只能是空的。

## 手機也要看：`--host` 與金鑰

複習紀錄只有跑 server 的那台電腦寫得進去，手機上不會有第二份筆記——所以沒有同步、
沒有衝突、也沒有離線評分。手機只是一塊遠端的螢幕，按下評分時寫檔案的還是你的電腦。

```bash
python serve.py --library --host 100.x.y.z     # Tailscale 給這台電腦的位址
```

`--host` 不給就維持 `127.0.0.1`，一切跟以前一樣。一旦給了，「外面連不到」這層保護就沒了，
所以**每一個請求都要帶金鑰**——包含只是想讀一張卡的那種：你在問什麼、哪些還沒懂，
並不比寫檔案的權限不敏感。

- 啟動時會印出一條 `…/?k=…` 的網址。手機用那一條打開，金鑰會被換成 cookie 並從網址上拿掉，
  之後同一個瀏覽器都不必再帶。**建議加到主畫面**，下次點圖示就好。
- 金鑰存在 `~/.paper-annotations/remote-key`，重開 server 不會變（不然手機的捷徑每次都失效）。
  要換一把就加 `--new-key`。**它不在 git 裡**，也不該放進 `papers.yml` 旁邊。
- 那條網址等於鑰匙：拿到的人看得到全部筆記，也改得了卡片。
- 位址建議用 Tailscale 給的那個，不要 `0.0.0.0`——綁所有介面連咖啡廳的 Wi-Fi 也答得出來，
  那時就只剩金鑰擋著。真的綁了，啟動訊息會提醒你。
- Tailscale 沒連的時候它給的位址還不存在，這時 `--host` 會綁不上，訊息會直說。

還沒做的：手機尺寸的版面與「加到主畫面」的 manifest（第二階段的步驟 3、4）。現在用手機開
是能用的桌面版面。

## 連結圖

書房頁上方有「論文清單／連結圖」兩個切換。連結圖分三層，每一層讀不讀得下去只由**那一層的
內容**決定，不會因為論文變多就整張變糊：

1. **書房層是一張方陣**：列是「從」、欄是「到」，格子裡是你在這兩篇之間接過的線。表格永遠不會
   有線互相交叉，四十篇也讀得完。分類可以先篩。
2. **點一格是那一對的頁面**：先印機械事實（誰在哪一節引用誰、原文那句話），再列你接過的線與
   反方向，最後列「共用標籤但還沒接」的候選。工具只把候選端到面前，不自己接。
3. **點任何一個筆記代號是那一則的鄰居**：指向它的、它指向的。這一層的大小只受那一則的連線數
   影響，跟總量無關。複習頁的卡片裡也有它，但只畫**第二圈**——第一圈卡片本來就印了。

**格子裡的大字是廣度，不是條數。** 兩篇之間四條線，可能是四個關係，也可能只是其中一篇某一節
的卡片特別多、全部從同一則發出。條數看不出差別，廣度可以：**兩邊各有幾則不同的筆記真的參與，
取比較窄的那一邊**。原始條數降級成小字，那一對的頁面會在灌水真的發生時明說是哪一種。

對角線放該篇自己的筆記總數，所以「這一列本來就筆記多」看得見，不必另外做正規化——除以總數會
得到一個沒人解釋得清楚的小數，比誠實的整數更糟。虛線框的格子是**有引用關係但你一條線都沒接**，
紅點是那一格裡有牴觸：一個牴觸比四個「改進了」值錢，用數量排它永遠沉在底下。

版面完全決定性：沒有力導向、沒有隨機，同一份資料畫一百次都一樣。

## 頁面左下角的「工具」

server 在跑的時候，複習頁與書房頁的**左下角**都有同一顆 `⚙ 工具`，位置與形狀一樣，
只有選單內容跟著頁面換。這些事本來就只是跑一行腳本，不必回到對話裡請 agent 代跑。

| 複習頁（這一篇） | 書房頁（全部） |
|---|---|
| 重建這一篇 | 更新書房頁 |
| 匯出 Anki | 盤點（誰引用誰、還有什麼沒解決） |
| 打包分享頁 | 全部重建 |
| 匯入畫記（貼上） | |
| 重新對位（先看差異） | |

規矩跟畫記存檔、複習評分同一條：

- 頁面送的是**動作名稱**，不是指令。server 有一張固定的動作表（`pa/actions.py`），
  腳本與路徑都從它自己掛載的論文查出來，請求裡的字串不會變成命令列的一部分。
- **一次只跑一件事**。有東西在跑的時候其他按鈕變灰並說在等誰。
- 腳本印的每一行**逐行出現**在左下角浮出的面板裡，最後給一行結果。警告不吞掉。
- **會改檔案的先看差異**：重新對位只跑 `--dry-run`，看過之後才會出現「把差異寫進卡片」；
  沒跑過那一步的話，連直接呼叫都會被 server 擋下來。沒有任何按鈕會刪東西。
- **產生檔案的給路徑**加一顆複製路徑——頁面不能自己把檔案交給你。
- **重建完不會自動重新載入**：那會換掉你正站著的這一頁，連捲動位置一起帶走。
  跑完給一顆「這一頁已經重建，重新載入」和一顆「等一下」。
- **沒有 server 時按鈕不消失**，變灰並說原因，滑上去顯示它等同的那一行指令。

複習頁的工具旁邊還有一顆 `← 書房`，回到書房頁。它**不是動作**，所以沒開 server 也能按：
從資料夾直接開的頁面走 `library.html` 的相對路徑，server 在跑就走 `/_pa/shelf`。
書房頁本身沒有這顆，只服務單一論文（沒有書房可回）的時候也不會出現——不會給你一顆按了 404 的按鈕。

複習頁頂端那段說明只會出現**第一次**，按 × 關掉之後就不再出現；想再看一次就從
同一顆工具按鈕裡的「這一頁怎麼用」叫回來。

啟動器因此只剩一個角色：把 server 開起來。

## 寄給別人

`/paper-annotations:share-page` 會產生一個**圖片全部內嵌的單檔**，放在論文資料夾裡
（`<論文名>-複習頁.html`），寄出去對方點兩下就能讀：不用裝 Python、不用開 server、
手機平板也行。他可以照樣畫記、寫註解、篩選、搜尋；想回饋給你就按「複製畫記」把內容
傳回來，你再用 `/paper-annotations:marks` 收進 `notes/marks/`。

要自己跑就是這一行：

```bash
python build_html.py <論文路徑> --embed-assets --to "<論文資料夾>/複習頁.html"
```

**`--to` 不要省略**：少了它會就地覆寫你自己在讀的 `annotated/index.html`，換成內嵌版，
下一次普通 build 又換回來。路徑寫絕對路徑的話，在哪個資料夾執行都可以。

內嵌之後檔案會明顯變大（一篇 15 張圖的論文大約 12 MB），超過 20 MB 就別走郵件附件了。
建置訊息會告訴你內嵌了幾張圖；有圖片找不到檔案也會**逐張報出來**，因為那代表收件人
會看到破圖。

server 幫不上這個場景——對方手上沒有 `notes/` 可以寫。所以這兩種模式不是二選一：
**自己讀用 server，分享用檔案。**

## 複習頁

`annotated/index.html`，一個檔案、離線可開、公式照樣渲染（KaTeX 內嵌）。

- **頁面就是一篇論文。** 卡片不佔版面，正文只多了幾處反白——**點反白的句子**才叫出
  當初的問題，蓋在畫面中間，關掉就繼續讀。疑問再多，論文也不會被撐開
- **好幾張卡引到同一處也分得開**：同一段、甚至同一句被好幾張卡引用時，每一處都會反白，
  重疊的地方顏色深一階。點下去會在點的地方列出這裡的卡，滑鼠移到哪一列，原文就亮起那張卡
  引的整句。段落左邊的**卡片標籤**列出掛在這一段的卡，超過 4 張收成「+N 張」；引文含公式
  而沒有反白的卡標著「無反白」，也在那裡。卡片右上角的 ⤴ 跳回原文，整句閃三下，沒有反白的
  卡閃整段。螢幕窄到放不下標籤時，標籤改排在段落上方
- **先看問題再看答案**：叫出來時最上面是你當初的提問，底下才是卡點、解答、一句話直覺——
  三段各自是一個色塊，掃一眼就知道在看哪一段。你自己寫過的話（猜的、解釋的）另成一塊
  「自己的話」，一句話直覺上標著是你寫的還是 AI 寫的
- **複習在側欄**：開頭一行「今天到期 N 張 · 半懂 M 張 · 下一張 …」，沒東西也會說是
  哪一種沒東西。到期的卡點開只看得到問題：先按想得起來／模糊／想不起來，才給一句話直覺
  和別篇論文的對照（先問你「另一篇怎麼做」，答案收在一個摺疊裡），要看卡點與解答再多
  按一下；最後評重來／困難／良好／簡單，按完會告訴你這張下次哪天回來，你說想得起來卻按
  了重來也會直說，不會自動跳下一張。答錯的當天再問一次，錯三次就明天再來。半懂的卡不
  評分：先用自己的話寫一遍，再對解答，對上了按「懂了，進排程」，你寫的話會記進卡片。
  評分與關掉半懂都要從 開啟書房.cmd 開的頁面才做得到；沒開 server 時一樣能分段自測，
  只是不記錄。對話裡貼的 `index.html#card-0007` 會直接開那張卡，`#review` 開複習區
- **側邊欄滑出式**：滑鼠移到左上角的 ☰ 就滑出來，蓋在論文上方——**論文一格都不會位移**。
  裡面是論文目錄與按論文順序排的疑問清單，點清單一樣叫出卡片（沒有反白的卡片也能從
  段落左邊的卡片標籤進入）。要它留著就點一下把手釘住；觸控裝置沒有 hover，也是用點的
- **右邊有提問草稿區**：讀完整段再一次把問題寫下來，不必讀到一半打斷去問。打開時
  論文會讓開，不會被蓋住；寫完按「複製」貼回對話。內容存在瀏覽器本機，重開還在。
  它只是草稿——不會送出，也不會自己變成卡片
- **螢光筆＋註解**：選取正文就會浮出調色盤，四個顏色，✎ 可以在那條畫記上寫一段話。
  畫完調色盤會留著，可以馬上改色或清掉；移開滑鼠、捲動頁面或按 Esc 就收起來。
  帶註解的畫記多一條虛底線，**滑鼠移上去就浮出註解**，點下去可以改。
  按側欄的「💾 存檔」寫進 `notes/marks/`，之後就跟卡片一樣進 git、重建也還在；
  已落檔的畫記在頁面上可以直接換顏色、改註解、刪掉，都是覆寫那個檔。
  對不上原文的畫記**不會被丟掉**，build 會逐條報出來
- **正文裡的「見 Fig. 4」「Table V」「Algorithm 2」可以點**，直接跳到那張圖表或那段
  演算法。`Fig.`／`Figure`／`Table`／`Algorithm` 加阿拉伯數字或羅馬數字都認得；
  `[13, Table V]` 這種指向別人論文的引用會跳過。對不到目標的引用維持純文字，並在建置
  訊息裡列出來，不會默默連到錯的地方
- **演算法自成色塊**：標題、步驟連在一起，不再是一段看起來像正文的編號清單
- **排版盡量忠於原文**：清單底下的 `a. b. c.` 保持縮排、標號照原文印（交給瀏覽器自動
  編號會把它改寫成 `1. 2. 3.`），腳註沿用論文自己的編號；選取反白用的是主題色，
  跨過公式也不會斷成一格一格
- **篩選**：依狀態（未解決／半懂／已解決）、隱藏 AI 主動標的卡、全文搜尋。
  選「不顯示疑問」連反白都熄掉，剩一份乾淨的論文
- **明暗主題**在右下角切換，跟隨系統或手動指定；打開提問草稿時它會被讓開的抽屜蓋住
- 要寄給別人就跑 `/paper-annotations:share-page`，圖片一併內嵌成單一檔案（見上面〈寄給別人〉）

## 段落檢查點

有些節的結尾會有一題，**答過了才看得到這一節的要點**——不然答案就在眼前。題目由 agent
從要點寫出來，放在 `notes/checks/`；要點少於六則的論文不會有檢查點。

- **先寫再對答案。** 寫一句（寫到卡住的地方也算），按「對答案」，這一節的要點就出來，
  你自己說答到了沒有——頁面上沒有 AI，能判斷的只有你，跟評分一樣
- **只問兩次。** 第二次換一句話問，還是沒答到就不再問第三次，改成記一張
  `origin: suggested` 的疑問卡進複習排程。「一直到會為止」發生在那裡，不在這裡
- **跳過是看得見的。** 「跳過，直接看要點」會直接打開這一節，目錄上標著跳過，
  想補答隨時按「現在補答」
- **目錄上一直看得到進度**：○ 還沒答 · ◐ 答過一次 · ● 現在這節 · ✓ 過了 · ⏭ 跳過 ·
  ✗ 成了卡片
- **「到這裡為止，這篇說了什麼」**是一個摺疊區，只放**前面已經過了的節**的要點。
  預設關著——二十幾節全部攤開就是把論文再看一遍
- 你寫的每一句都會記進那個檢查點的 `## 自己的話`，作答紀錄追加在
  `notes/checks/answers/`，跟複習紀錄一樣只加不改。**要記錄就得從開啟書房.cmd 開的
  頁面答**；沒開 server 一樣可以自測，只是頁面會直說這次不會留下來

## 整理

`/paper-annotations:digest` 讀卡片和原文，寫一份給你自己的整理。**不做論文摘要**——
那是 SciSpace、Scholarcy 那類工具的活，而且對讀完並卡過的人沒用。

| 模式 | 產出 | 什麼時候用 |
|---|---|---|
| `review-sheet` 回顧單 | 按論文順序，一節一行：這節在做什麼、你的疑問、狀態 | 重讀之前，五分鐘掃出還有哪幾節沒通 |
| `theme-map` 主題聚合 | 把散在不同節、其實同一件事沒通的疑問併組，附重讀順序 | 疑問彼此有牽連時；這是自己最難做的一種 |
| `prerequisites` 前提盤點 | 從卡點反推缺的背景知識，指出去哪補 | 同一個概念反覆出現在不同卡點時 |
| `connections` 接線 | 先列誰引用誰，再把這篇的段落接到別篇的卡片與要點：關聯、共識、矛盾 | 讀了第二篇以後，每讀完一篇跑一次 |
| `claims-check` 主張核對 | 你自己寫的一段（相關研究、提案），逐句對你的筆記：有依據、對不上、找不到依據 | 開始寫東西的時候；它只核對，不替你寫 |

回顧單和主題聚合**只列問題不給答案**，答案在卡片裡展開就有。整理寫到
`notes/digests/`，是額外產物，不影響建置。

**整理不是冪等的**：`annotated/` 可以隨時重生，整理不行——同樣的卡片再跑一次不會得到
一樣的文字。想留舊版就先改檔名。

## 匯出

`/paper-annotations:export-cards`，或直接跑：

```bash
python export_cards.py <論文路徑> --format anki --status resolved,half
```

`## 問題` → Front，`## 解答` → Back，卡點、直覺與原文引文進 Extra；`$…$` 會轉成 Anki
的 MathJax 寫法（`\(…\)`），匯進去就會渲染。也支援 `--format csv` 與 `json`。

預設不匯出 `open` 的卡——還沒有解答的問題，做成問答卡背面是空的。匯出是唯讀的，
卡片本身不會被改動。

## 指令

| 指令 | 用途 |
|---|---|
| `/paper-annotations:setup <論文資料夾>` | 設定新論文，判定支援程度，首次建置 |
| `/paper-annotations:build [路徑]` | 重新產生註記檢視與複習頁，回報所有警告 |
| `/paper-annotations:review [路徑]` | 盤點還有哪裡沒懂 |
| `/paper-annotations:digest [路徑] [模式]` | 把疑問與原文合成一份整理：回顧單、主題聚合、或前提盤點 |
| `/paper-annotations:export-cards [路徑] [格式]` | 把卡片資料匯給別的程式：Anki 匯入檔、CSV 或 JSON |
| `/paper-annotations:marks [貼上畫記]` | 把「複製畫記」的內容存成 `notes/marks/` 並重建 |
| `/paper-annotations:share-page [路徑]` | 把複習頁打包成單一 HTML 檔寄給別人（圖片全部內嵌） |

平常**不需要指令**：直接問論文問題，疑問會自動累積成卡片。
